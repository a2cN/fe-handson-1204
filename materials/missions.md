# 問題文

商品一覧のアプリを題材に、データの取得を TanStack Query に置き換えていきます。

- 必須は **ミッション1・2** です。全員でここまで進めます。
- 早く終わった人は、**発展1〜4** に進んでください。1 → 4 の順がおすすめです。

## はじめに

### 起動

```sh
npm ci
npm run dev
```

ブラウザで http://localhost:5173 を開きます。

### 画面の見方

- **左側:** 商品のページ。ここが課題の画面です。
- **右側の上:** 「今やること」のカード、バッジ、「判定する」ボタン。カードには、今の課題の目標、編集するファイル、判定の前にする操作が出ます。バッジを押すと、その課題のカードに切り替わります。
- **右側の下:** API リクエストの回数と履歴。⏱ が付いたリクエストには、わざと3秒の遅延が入っています(商品一覧の取得だけ)。「エラーを発生させる」をオンにすると、API がエラーを返します。

### ルール

- **編集するのは `src/mission/` の中だけです。** ほかのファイルは触らなくて大丈夫です。
- 課題のファイルの先頭にも、この問題文と同じ内容がコメントで書いてあります。
- できたと思ったら、画面右上の **「判定する」** を押します。判定は、実際に画面を操作した結果で行います。コードを書いたら、画面でも操作してから押してください。
- 判定でまだの課題には、足りない条件が表示されます。次に何をすればよいかのヒントにしてください。
- AI の利用は特に禁止しませんが、まずは自分の手で書いてみることをおすすめします。

## ミッション1: `useQuery` に置き換える(必須)

| 項目 | 内容 |
|---|---|
| 編集するファイル | `src/mission/ProductListPage.tsx` |
| 画面 | http://localhost:5173/ |

**今の状態:** 商品一覧を `fetch + useEffect` で取得しています。読み込み中やエラーの状態も、`useState` で自分で管理しています。

**やること:** TanStack Query の `useQuery` に置き換えます。読み込み中とエラーの表示も、`useQuery` が返す状態を使って出します。

**ヒント:** 取得する関数は `fetchProducts`(`src/api/products.ts`)が、もう用意されています。

**正解条件:**

- [ ] `useQuery` で商品一覧を取得している
- [ ] 読み込み中は `<LoadingView />` を表示する
- [ ] エラーのときは `<ErrorView />` を表示する

エラーの表示は、画面右の「エラーを発生させる」をオンにして、ページを再読み込みすると確かめられます。`useQuery` は失敗すると自動で再試行するので、エラーが表示されるまで約20秒かかります。

## ミッション2: キャッシュを体験する(必須)

| 項目 | 内容 |
|---|---|
| 編集するファイル | `src/mission/ProductListPage.tsx`(ミッション1の続き) |
| 画面 | http://localhost:5173/ |

**今の状態:** ミッション1を終えた状態で、一覧 → 商品をクリックして詳細 → 「一覧へ戻る」と操作してみてください。一覧は**すぐに表示されます**が、右の欄を見ると、一覧のリクエストが**また出ています**。

**やること:** 一覧に戻ったとき、しばらくの間はリクエストが出ないようにします。

**ヒント:** `useQuery` には、取得したデータを「新鮮」とみなす時間を決めるオプションがあります。

**正解条件:**

- [ ] 一覧 → 詳細 → 一覧と戻ったとき、一覧のリクエストが増えない

## 発展1: 商品詳細を `useQuery` に置き換える

| 項目 | 内容 |
|---|---|
| 編集するファイル | `src/mission/ProductDetailPage.tsx` |

**今の状態:** 商品の詳細を `fetch + useEffect` で取得しています。同じ商品を開くたびに、取得し直しています。

**やること:** 一覧と同じように、`useQuery` に置き換えます。

**正解条件:**

## 発展2: 検索条件を Query Key に含める

| 項目 | 内容 |
|---|---|
| 編集するファイル | `src/mission/SearchPage.tsx` |
| 画面 | http://localhost:5173/search(画面上部の「検索」) |

**今の状態:** すでに `useQuery` を使っていますが、キーワードを入れて検索しても、結果が最初の一覧のまま変わりません。

**やること:** キーワードを変えたら、結果も変わるように直します。

**ヒント:** TanStack Query は、`queryKey` が同じなら「同じデータ」とみなします。

**正解条件:**

- [ ] 2種類以上のキーワードで検索し、キーワードごとに別のキャッシュができている(`queryKey` にキーワードが含まれている)

## 発展4: `useMutation` と `invalidateQueries`

| 項目 | 内容 |
|---|---|
| 編集するファイル | `src/mission/PurchaseButton.tsx` |
| 画面 | 商品詳細の「購入する」ボタン |
| 前提 | 一覧(ミッション1・2)と詳細(発展1)が `useQuery` になっていること |

**今の状態:** 「購入する」を押すと、サーバー側の在庫は1つ減ります。ところが、詳細や一覧に表示される在庫は、古いまま変わりません。

**やること:** `useMutation` で購入するように書き換えます。購入が成功したらキャッシュを無効化して、表示を最新の在庫に変えます。

**ヒント:** `useQueryClient()` で QueryClient を取り出せます。`invalidateQueries({ queryKey: ['products'] })` は、`['products']` で始まるキーのキャッシュを、まとめて無効化します。

**正解条件:**

- [ ] `useMutation` で購入している
- [ ] 購入が成功したあと、商品データが取得し直される(在庫の表示が最新になる)

商品の在庫は、`npm run dev` を起動し直すたびに初期状態に戻ります。
